# آزمون‌ریپ: سند طراحی رابط (هویت «قله»)

این سند ظاهر و جریان اپ دانش‌آموز و مدیر را تعیین می‌کند. منطق محصول (موتور تکرار، بانک سؤال) در `../DESIGN.md` است.

## ۱. اصل‌ها

1. **هر صفحه یک اقدام اصلی.** فقط یک دکمهٔ سبز در هر صفحه هست.
2. **اول بده، بعد بخواه.** کاربر اول سؤال حل می‌کند و نتیجه می‌بیند؛ بعد اسم، بعد شماره.
3. **انتخاب کم، از قبل پر.** پایه، کتاب‌ها و حجم روزانه پیش‌فرض دارند؛ کاربر فقط تأیید می‌کند.
4. **مرحله‌به‌مرحله.** هیچ فرمی بیش از یک سؤال در هر مرحله نمی‌پرسد.
5. **هر نقش فقط کار خودش را می‌بیند.** دانش‌آموز: امروز و مسیر. مدیر: صف بازبینی.
6. **رنگ، اندازه و سایه معنی دارند.** هر چیز تزئینی حذف می‌شود.

### آیکون‌ها (`src/Icons.jsx`)
اختصاصی، شبکهٔ ۲۴، خط ۲٫۲ با سر و گوشهٔ گرد، رنگ خط = رنگ متن. **هر آیکون دقیقاً یک جزء توپر سبز دارد** (پرچم، نقطهٔ مقصد، دستگیره)، که همان موتیف «پرچم روی قله» است. آیکون‌های جهت‌دار (پیکان، بعدی) در RTL آینه می‌شوند.

### ماسکوت «قله» (`src/Mascot.jsx`)
کوهی مشکی با دو چشم و پرچم سبز. سه حالت: عادی، خوشحال (پرچم بالا، لبخند)، دلگرم‌کننده (بعد از اشتباه). فقط در سه جا دیده می‌شود: امروز، کارت نکته، پایان جلسه.

### حرکت
- جواب درست: پرش کوتاه ماسکوت (۳ پیکسل، ۳۰۰ میلی‌ثانیه).
- نوار پیشرفت: پر شدن ۳۵۰ میلی‌ثانیه.
- هیچ حرکت دیگری نیست. `prefers-reduced-motion` همه را خاموش می‌کند.

## ۳. جریان دانش‌آموز

```
فرود (سؤال ۱) → سؤال ۲ → سؤال ۳ → نتیجه + برنامهٔ آماده → اسم → شماره → کد → امروز
                                                                                   │
                                     امروز → جلسه (نکته → سؤال → بازخورد)… → پایان → امروز
                                     مسیر → فصل → تعیین سطح / تمرین فصل
```

| صفحه | محتوا | اقدام اصلی |
|---|---|---|
| فرود | یک جمله و یک سؤال واقعی از بانک | انتخاب گزینه |
| بازخورد آزمایشی | درست/غلط، نکتهٔ سؤال | بعدی |
| نتیجه | «از ۳ نکته N تا را بلدی»، برنامهٔ پرشده (پایه، روزی ۲۰ سؤال) | همین خوب است |
| اسم | یک فیلد | ادامه |
| شماره، کد | یک فیلد در هر مرحله | ذخیرهٔ برنامه |
| امروز | عدد بزرگ سؤال‌ها، دقیقه، اشتباه‌های دیروز، پیشرفت فصل، هفته | شروع |
| جلسه | یک سؤال؛ نوار پیشرفت؛ خروج گوشه | پاسخ / بعدی |
| پایان جلسه | N از M، نوار نتیجه | تمام |
| مسیر | فصل‌ها روی یک خط با «۹ از ۱۶»، نکته‌ها زیر هر فصل | تعیین سطح یا تمرین همان فصل |
| تنظیمات (پشت آواتار) | نام، حجم روزانه، تاریخ آزمون، اندازهٔ متن، برنامه، خروج | ذخیره |

ناوبری پایین فقط دو مقصد دارد: **امروز** و **مسیر**.

اگر بانک هنوز سؤال تأییدشده ندارد، فرود بدون سؤال آزمایشی مستقیم به «برنامهٔ آماده» می‌رود.
جواب‌های آزمایشی بعد از ثبت‌نام به حساب منتقل می‌شوند: نکته‌ای که درست زده شده سه روز بعد مرور می‌شود.

## ۴. جریان مدیر

صف بازبینی هم یک «جلسه» است: یک سؤال کنار اسکنش، سه اقدام (تأیید، اصلاح، رد با یادداشت) و بعد از هر تصمیم، سؤال بعدیِ در انتظار خودکار باز می‌شود. پوشش نکته‌ها، گزارش‌ها، آمار و ورود داده در تب‌های دیگرند.

## ۵. قاعده‌های ضداسلاپ

- عنوان‌ها مشخص‌اند («سؤال امروز»، «فصل ۱، مجموعه‌ها: ۹ از ۱۶»)، نه خوشامد.
- کارت‌های هم‌وزن کنار هم نیست؛ در هر صفحه یک عدد قهرمان است.
- کاشی آیکون رنگی، نشان سبز تزئینی و ایموجی در رابط دانش‌آموز نیست.
- وضعیت نکته‌ها فقط با سه نشانه: توپر سبز (یادگرفته)، توپر مشکی (در حال یادگیری)، توخالی (شروع‌نشده). قرمز فقط برای «آخرین بار اشتباه».
